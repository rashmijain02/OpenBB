## Batch A: chart widgets

### What changed

Ten Terminal chart widgets now return a Plotly figure by default; `raw=true` returns the
pre-#1268 rows unchanged (same values and JSON number types, frozen in
`tests/unit/fixtures/terminal_chart_rows_1268.json` before any code change):
`pi_charting`, `pi_equity_financial_charts`, `pi_equity_price_history`, `pi_paper_performance`,
`pi_price_target_history`, `pi_revenue_business_line`, `pi_revenue_geography`,
`pi_risk_vol_chart`, `pi_stock_ownership`, `pi_xray_country`.

- New `widget_backend/terminal_charts.py` (sibling of `overview_charts.py`, reuses its
  `layout` / `note` / `header_note` / `state_figure`). `plotly_chart(builder)` wraps an existing
  `@with_chain` endpoint: it adds a `raw` query parameter, validates rows through the endpoint's
  declared return annotation (exactly what FastAPI's inferred response model did, so raw output is
  byte-compatible, e.g. financials `year` stays `2021.0`), and builds the figure from those rows.
  No financial math; every plotted value is a row value, unscaled.
- Trace choices: candlestick + volume bars on a lower `y2` pane (price history candle mode);
  candlestick + SMA20/SMA50 lines + RSI14 on a 0-100 `y2` pane (charting); dated lines (price
  history line mode, price targets, rolling vol, paper equity); grouped bars ($B, left) + net
  margin line (%, right `y2`) for financials; pies only for shares of a whole (country weights,
  revenue by region/segment, ownership split).
- States: `layout.meta = {state, source}`. `source` is the tier that served the request
  (`stub` or e.g. `fmp_cached`), read from a new per-request `SERVING_TIER` context variable that
  `record_tier_used` sets (race-free, unlike the shared `_TIER_IN_USE` ledger). `state` is `live`
  (tier data, no annotation), `demo` (stub; header annotation says sample/synthetic data),
  `unavailable` (non-demo account on the account-scoped widgets; trace-free figure + message) or
  `empty` (no rows; trace-free figure + message).
- No-title rule (lead decision): no figure sets `layout.title`, including the #1267 figures
  (`pi_xray_sector`, `pi_brinson_attribution`); their book/window/benchmark text moved into the
  annotation. Glossary keys are on `trace.meta.glossaryKey`; hover text repeats the Local Viewer
  glossary summary.
- `widgets.json`: removed `data.chart` / `data.metricGlossary` for the 10 widgets and `help` on
  `pi_equity_price_history`; essentials (units, axes, candle reading guide, demo labelling, raw
  row shape) moved into `description`.
- `workspace_contract_debt.json`: removed 23 #1268 entries (10 `response.shape.chart`,
  12 `widget.data.unknown_key`, 1 `widget.unknown_key` for `pi_equity_price_history.help`);
  81 -> 58. Table/metric/markdown/glossary entries on non-chart widgets are untouched (batch B).
- `scripts/build_portfolio_workspace_matrix.py`: detects Plotly chart routes statically (route
  function takes `raw`, or is decorated with `plotly_chart`), adds `chart.plotly`, and classifies
  such charts `native-ready` (account-scoped demo widgets stay `explicit-demo`). TechTrade charts
  (#1271) stay `contract-repair`. `native_workspace_matrix.json` regenerated by the script.

## Batch B: table, metric, and Markdown contracts

HEAD `3895214dd` (batch A, local); batch B is uncommitted on top of it (the lead commits).

### What changed

All 50 remaining #1268 debt entries are cleared (`workspace_contract_debt.json` 58 -> 8; the
8 left belong to #1270 and #1271). The served manifests carry no `data.metricGlossary`,
`data.metric`, `columnsDefs[].glossaryKey` / `valueLabels`, or `data.table.rowLabels` /
`rowLabelPatterns`.

- **Glossary (lead decision 1).** The 19 columns that had `glossaryKey` now carry the
  schema-native `headerTooltip`, set to the Local Viewer glossary record's one-line summary
  (verbatim; a test compares each to `index.html`). Widget-level glossary that mattered moved
  into `description` (technicals pivot/resistance/support; metric units and demo state;
  revenue units).
- **Value labels (decision 2).** Workspace has no value-label renderer (`renderFn` values are
  `greenRed`, `titleCase`, `hoverCard`, `cellOnClick`, `columnColor`, `showCellChange`, and
  `titleCase` cannot produce `Form 8-K` / `13F Increase`), so the endpoint returns the label:
  event type, smart-money activity, alert type, basket consensus (`BUY` -> `Buy`, `STRONG_BUY`
  -> `Strong Buy`, ...). Unknown codes pass through unchanged.
- **Row labels (decision 3).** Technicals, analyst forecasts (exact labels plus the
  `Rating Distribution: ...` and `Qn YYYY EPS Surprise` patterns) and the What-If card are
  labelled in the response. New `widget_backend/table_contracts.py`: `relabel(field, labels,
  patterns)` wraps the `with_chain` endpoint, so a future provider tier is labelled too, and
  `label_rows` copies rows (the shared demo basket keeps its codes).
- **Metrics (decision 4).** The four metric endpoints return Workspace cards
  `[{label, value}]` plus a trailing `{"label": "Data State", "value": "Demo: ..."}` card.
  A non-demo account returns `"Unavailable"` for every value and
  `Data State = "Unavailable: account resolver not wired for this account"` instead of the
  old fabricated `0.0`. Risk values are percentage points (`Annualized Volatility (%)` 18.4,
  `1-Day 95% VaR (%)` -2.1; beta stays a ratio). No `raw=true` dict form: no consumer needed it.
- **Units (decision 5).** `_shape_revenue_geography` / `_shape_revenue_business_line` convert
  provider absolute currency to millions (`_to_millions`, 2 dp), matching the stub. Pie hover
  says `Revenue (millions)`; both descriptions say millions of the reporting currency.
  `test_live_and_demo_revenue_rows_share_one_unit` fails on mixed units.
- **Markdown (decision 6).** The eight `pi_*` Markdown widgets already returned non-empty
  text; a new test pins that every one is non-blank and every data-bearing one says demo /
  stub / preview / sample / unavailable in words (the two context widgets are exempt).
- `scripts/build_portfolio_workspace_matrix.py`: dropped `metricLabels` (labels now live in the
  response); a metric manifest is `native-ready`. Fixture regenerated (only `metricLabels`
  lines removed; no baseline state changed).
