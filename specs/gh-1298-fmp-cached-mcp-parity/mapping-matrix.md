## Findings

**1. Raw vs normalized storage.** Four distinct behaviours:
- RAW and READ (reproducible byte-for-byte after `json.loads`): `balance_sheet`, `income_statement`, `cash_flow`, `key_metrics`, `financial_ratios` (`data_json` = `json.dumps(item)`, read back as the fetcher's `aextract_data` output: `models/balance_sheet.py:147-165,195-220`; same shape in the other four), `equity_profile` (`models/equity_profile.py:114-131`), `equity_peers` (`:120-150`), `equity_quote` (`models/equity_quote.py:125-142,168`), `etf_holdings` (v3 `etf-holder`, not hosted), `institutional_ownership` (not hosted), and `ttl_cache.payload` for ExchangeMarketHours (`models/base_cached.py:~226-286`).
- NORMALIZED columns only (raw not recoverable): `equity_historical` (typed OHLCV columns; `change`->`change_amount`; unknown fields into `additional_fields`; synthetic holiday gap-fill rows with `is_filled`), `equity_intraday_historical`, `aftermarket_quote`, `analyst_estimates` (`utils/cache_manager.py:_store_record`, `models/equity_historical.py:1193-1262`).
- RAW but WRITE-ONLY: every `_SymbolListFetcherBase` / `_AvailableDirectoryFetcherBase` fetcher (stock/etf/cik/available-*/commodities/crypto/forex/index lists, constituents, historical constituents, COT list, market-risk-premium, symbol-change, shares-float-all) does `TRUNCATE` + `INSERT data_json` on every call (`models/available_directories.py:104-135`, `symbol_lists.py:105-116`) but always fetches live first; no read path. `analyst_grades` is the same (`models/analyst_recommendations.py:288-330`).
- NOTHING stored: the `_SearchFetcherBase` family (`models/search_endpoints.py:126-155`: search, analyst_ratings, sector_performance, statement_extras incl. DCF, stock_quotes, single_param, as_reported, w5_w6_w8_extras, economic_indicators; `Fetcher._fetch` is a bare `httpx` GET, comment 'live pass-through') and every `create_cached_fetcher_class` fallback (`models/base_cached.py:51-104`; `assets/persistence_descriptors.json` lists 57 `non_persistent_fallbacks`: credential translation only, even where a table exists in `FLATTENED_TABLES`).

Even for RAW/READ rows, `/fmp_cached/*` routes and std-OpenBB commands return OBBject results after `transform_data` (snake_case aliases, pydantic models; `extra=allow` keeps unaliased keys), not the FMP JSON. A byte-for-byte hosted reproduction needs either a new raw-passthrough route reading `data_json` or a change to store/return raw rows.

**2. TTL configuration.** Not config-driven. Each reader hard-codes a constant and a `cached_at >= now - TTL` predicate: balance_sheet/cash_flow/income_statement/key_metrics/financial_ratios/etf_holdings = 1 day (`*_TTL_DAYS = 1`, e.g. `models/balance_sheet.py:23`), equity_profile/equity_peers/institutional_ownership = 7 days, equity_quote = 300 s (`models/equity_quote.py:23`), aftermarket_quote = 60 s (`models/aftermarket_quote.py:38`), ExchangeMarketHours = 86400 s via `create_ttl_wrapper_class` (`models/exchange_market_hours.py:24`). `utils/cache_schema.py:6059-6075` `CACHE_EXPIRY_RULES` mirrors these for pruning only (`prune_expired_cache` :6186, CLI `utils/cache_prune.py`; allowlist `EXPIRABLE_CACHE_TABLES` :6031). Every other table is non-expiring (`cache_schema.py:5990-5996`): equity_historical, equity_intraday_historical, analyst_estimates, all directory tables, sp500_constituents (serves stale rows as fallback; 7d code TTL, `models/index_constituents.py:66`). Expiry only means 'reader refetches'; stale rows are not deleted unless pruned manually. The TTL column below shows seconds, or `non-expiring`, or `none` (nothing cached).

**3. plan_limited.** `utils/plan_limited.py:44` `_PLAN_LIMITED` = 57 dict entries `{tier, since, notes}` keyed by OpenBB model name (not URL), e.g. CryptoSearch, EquityActive, IndexConstituents, EtfEquityExposure, EarningsCallTranscript, *Ttm statements, *Bulk, Tipranks*, Batch*Quotes, Funds*. Helpers `is_plan_limited/get_plan_limit/all_plan_limited` (:317-327) are referenced only by tests/coverage reports (`tests/test_two_provider_coverage.py`, `test_persistence_contract.py`), NOT by runtime fetchers or the MCP server: a plan-limited call still hits FMP and fails with 402. Hosted endpoints touched: most-active (EquityActive), cryptocurrency-list (CryptoSearch hits the same URL), sp-500 (IndexConstituents), financials-latest (? LatestFinancialStatements).

**4. How routes are exposed (MCP).** `assets/model_routes.json` lists 112 `fmp_cached_<command>` routes (mostly `providers: [fmp, fmp_cached]`; `analyst_recommendations` is fmp_cached only). `mcp_server/tests/app/test_fmp_route_policy.py` asserts every manifest command is admitted by the `platform-standard`, `portfolio-read`, `portfolio-ops` capability profiles by exact operation name (`fmp_cached_<command>`), an unlisted `fmp_cached_future_route` stays denied, and every route is invocable. The std-OpenBB fetchers (BalanceSheet, EquityProfile, EquityHistorical, ...) are exposed through the regular OpenBB routers with `provider=fmp_cached`, not under `/fmp_cached/`.

**5. Caveats worth knowing.**
- balance/cash/income/key_metrics/ratios cache key is `symbol` only; `replace_rows` DELETE+INSERTs all rows of the symbol (`utils/database.py:367`), so alternating annual and quarter calls evict each other; hit returns `limit or 5` rows after an in-memory period filter, possibly fewer than a hosted `limit`.
- `_SearchFetcherBase` sends exactly one query field, so multi-param hosted endpoints (limit/page/from/to/period) are only partly reachable even live.
- Hosted slugs `grades-summary`, `historical-grades`, `historical-ratings` map to FMP `grades-consensus`, `grades-historical`, `ratings-historical` (?).
- Quote/aftermarket/gainers rows are tagged `not-cacheable` (real time) even where a TTL cache exists (equity_quote 300 s, aftermarket_quote 60 s).
