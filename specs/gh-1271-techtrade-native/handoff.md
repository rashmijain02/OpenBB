## What changed

- **Debt.** The five #1271 entries are gone; `workspace_contract_debt.json` is now empty (5 -> 0).
  The file stays as the shrink-only guard (`validate_portfolio_workspace_manifests.py` reads it).
  `validate --strict`: `61 widgets, 3 apps, 0 issues`.
- **Charts (Plotly, `raw=true` rows, no `layout.title`).** New `widget_backend/techtrade_charts.py`;
  both endpoints are wrapped by the existing `plotly_chart` and return row lists:
  - `tt_segment_movers`: bar of each segment's strongest mover (`change_pct`, unscaled; bar text = symbol).
  - `tt_simulate_result`: line of marked P&L by simulation day (one trace per segment; name carries the symbol).
  - Snapshot provenance in `layout.meta` (`source=eod-snapshot`, `asOf` = session) plus the header
    annotation from `finish`; a footnote repeats the disclaimer / survivorship / earnings warning.
  - No snapshot -> trace-free `unavailable` figure; a completed run with no rows -> `unavailable`
    "latest EOD snapshot completed with no ..." (new `_mark_no_rows`, as-of kept).
- **Scan table.** Returns the row array (no `{"rows": ..., computed_at, ...}` envelope, no `dataKey`).
  `columnsDefs` (17 fields: plan columns, snapshot badge, the three provenance columns with
  `hide` on source/as-of). Five `headerTooltip`s are new Local Viewer glossary records
  (`signal_score`, `entry_price`, `stop_loss_price`, `profit_target_price`, `reward_to_risk`).
- **Click-through (supported, implemented).** Symbol column: `renderFn: cellOnClick`,
  `renderFnParams: {actionType: groupBy, groupBy: {paramName: symbol}}`. The pinned runtime
  (`terminalpro/.../useCellOnClickHandler.ts`) updates a `ticker` group only when
  `groupBy.paramName` equals the clicking widget's own ticker param (`getTickerParamName`), so the
  table carries a hidden `symbol` ticker param (`show: false`, per app-builder `layout-grid.md`).
  The endpoint ignores `symbol`. Not verified in a live Workspace browser.
- **Privacy.** (a) `snapshot/store.py`: new `display_db_path()`; the MySQL-fallback WARNING logs
  `~/.portfolio_intel/snapshot.db` (home-relative) or the file name only (outside home).
  (b) JSON `/tt/execute/paper-status` returns `account_display(account_id)`.
- **Boundaries.** No behaviour change was needed: every TechTrade widget endpoint and
  `pi_paper_ticket` is GET-only and never reaches an order seam. New tests prove it (below).

## Decisions for the lead

1. `tt_order_legs`, `tt_validation_verdict`, `tt_tuning_report`, `tt_audit_journal` stay without
   `columnsDefs` (matrix `contract-repair`): valid Workspace tables, but their rows are
   engine-defined (validation/tuning reports are nested); declaring columns would be speculative.
2. A completed snapshot with no rows is now `unavailable` for the two charts and the scan table
   (other TechTrade tables keep `cached` + note row, unchanged).
3. The envelope fields `computed_at`, `is_stale`, `is_partial`, `missing_segments` are gone from
   the scan table / movers; freshness lives in row `freshness` / `snapshot_badge` and the
   provenance state.
4. `pi_paper_ticket?confirm=true` says "COMMITTED ... (stub)" but writes nothing (proved). Wording
   is misleading; follow-up candidate, not changed here.
